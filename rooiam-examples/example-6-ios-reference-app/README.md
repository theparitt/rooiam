# iOS reference source (experimental)

This is a small host-app example for [`RooiamPhoneSDK`](../../rooiam-sdk/ios). It demonstrates app-owned WebKit login cookies, physical QR scanning, explicit browser and API-key review, enrollment and revoke. It is source-only until built on macOS; no iOS build or device test has occurred in this environment.

On a Mac, create an **iOS App** target in Xcode named `RooiamReference`, SwiftUI lifecycle, iOS 16+, with a unique bundle ID. Add the local package at `../../rooiam-sdk/ios` and link `RooiamPhoneSDK`. Add `RooiamReferenceApp.swift`, `ContentView.swift` and `QRScanner.swift` to the app target. In Signing & Capabilities enable **App Attest** and add `NSCameraUsageDescription` (`Scan a Rooiam sign-in QR that you started in your browser.`) in `Info.plist`. Use a development team/provisioning profile that includes the capability. Set the server's Apple App ID prefix and app allowlist before testing enrollment. The sample requests App Attest `development` in DEBUG; use a **staging server** with development attestation explicitly allowed. Release builds request `production` and must pass the normal strict policy. Do not relax production policy for a debug build.

Open the app on an iPhone, enter the trusted Rooiam **API origin**, tap **Sign in**, then complete Rooiam login in the embedded WebKit view. Return and tap **Enroll this iPhone**. In a new browser session choose phone sign-in, scan its QR, compare the exact code and number, then approve. For an API-key QR, inspect the workspace, key label, permission preset, permissions, expiry and code before approving. If a decision request times out, inspect the browser before starting a new QR; the SDK will not resend it automatically.

The example uses `WKWebsiteDataStore.default()` for cookies, so production apps should replace this with their own session provider. It keeps a short-lived QR request ID to re-fetch after app relaunch. It does not persist a decision in progress; an interrupted approve is uncertain and must be checked in the browser. For a complete deployment guide and explicit untested gates, read [the iOS integration guide](../../docs/reference/18_ios_experimental_integration.md).
