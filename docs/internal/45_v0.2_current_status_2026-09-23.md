## Operations and release constraints

- Workspace opt-in defaults off; the platform gate must also permit login.
- Migration 0062 rejects duplicate public keys; operators must investigate and resolve duplicates before upgrade.
- Android wraps its Ed25519 seed with Keystore AES-GCM, then signs in memory. This is not hardware-backed Ed25519.
- Lost completion responses require a new intent. Committed MFA challenges and sessions follow their existing lifecycle; device revocation does not retroactively revoke them.
- Production vendor configuration and app distribution require separate evidence.
- Earlier documentation/landing deployment is separate from deployment of this authentication implementation. No production authentication deployment is claimed.

Keep release gates open until their required environments have been exercised. Code, automated tests, hardware evidence and operator walkthroughs are distinct.

## Phase D reference application

`rooiam-examples/example-4-reference-app` now provides the missing application-owned callback/session example. Its browser receives only a random `HttpOnly` application cookie. OAuth state, S256 PKCE verifier, confidential-client secret, Rooiam access token, local subject mapping, CSRF token and session data stay on the backend. Callback transactions are consumed before exchange, so concurrent or replayed callbacks cannot mint duplicate sessions.

The reference uses in-memory stores to keep the example inspectable; production adopters must replace them with their durable application database/session store. This completes the code-and-automated-evidence portion of item D. The independent clean-clone walkthrough with a physical phone remains the Phase D exit gate.
