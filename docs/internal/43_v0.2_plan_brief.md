## Adaptations to the supplied proposal

| Proposal | Current implementation | 0.2 decision |
|---|---|---|
| New `/v1/auth/transactions` and `/v1/devices` APIs | `/v1/auth/device-login/*` and `/v1/identity/me/devices` | Extend existing routes; do not introduce a parallel login engine |
| `CREATED → CLAIMED → APPROVED → CONSUMED` | `pending → approved → consumed`; rejection/cancellation from pending; effective expiry | Document existing transitions first. A claim state needs an explicit security benefit and migration |
| QR includes a scan secret | `rooiam://device-login?server=…&public_id=…` | Review interception/relay and origin substitution. A scan secret is a proposed protocol change, not an existing field |
| PKCE verifier + separate authorization code | Browser nonce hash and user-agent binding; `/complete` consumes the intent; downstream OIDC already uses PKCE | Review binding and completion guarantees. Do not describe the nonce as PKCE or invent a second token exchange |
| Three-digit matching code | Two-digit number choices (`10..99`) plus a separate six-digit display code | Keep exact current fields in clients. A UX/length change must update the contract, SDK and tests together |
| 120-second intent / 30-second grant | Configurable `device_login_expiry_minutes`, default five minutes; no separate device grant | Validate settings and expiry boundaries; new lifetimes require a documented decision |
| P-256 device identity in Android Keystore | Ed25519 device approval key and hashed device token | Resolve supported Android storage/signing before implementation; never silently change the server algorithm |
| Attestation entirely deferred | Server already gates approval through attestation verification | Preserve the gate and document vendor configuration and compatibility limitations |
| Rust SDK and repository rewrite required | Two TypeScript packages and existing test runners | Extend these first; Rust SDK is deferred until a real consumer needs it |

## Phase A — Freeze the supported contract

- [ ] Document every state transition, effective expiry, error, request field, signing byte sequence, retry behavior and protocol-version handling against the implementation.
- [x] Preserve rejected/cancelled/consumed as terminal after expiry; regression test passes.
- [x] Keep approved requests non-cancellable; document reload, lost response and abandoned approval recovery.
- [ ] Threat-model QR substitution/relay, stolen browser nonce, stolen device token, signature replay, cross-client/workspace confusion and malicious server URLs. Number matching is a human check, not a phishing-resistance guarantee.
- [x] Bind phone credentials to the enrolled origin; reject substitution, insecure production origins and automatic redirects. Parser tests pass; hardware walkthrough remains Phase C.
- [x] Specify API 26 minimum and Keystore AES-GCM wrapping of Ed25519 seed. Signing is in memory; hardware tests remain open.
- [x] Record preview protocol version and workspace schema upgrade; synchronize the mobile contract and OpenAPI.

Exit: a reviewed contract and executable test matrix. No new QR fields or fictional SDK calls in published integration instructions.

- [ ] Validate registered workspace/client context and server-resolved callbacks at start and completion. Check membership, suspension, policy changes and MFA without allowing cross-tenant escalation.
- [x] Lock approving devices against concurrent revocation; test revocation after approval and document the committed-result cutoff.
- [x] Make consumption and session/MFA insertion transactional; test insert failures and mixed concurrent result creation, and document lost-response recovery.
- [x] Exercise PostgreSQL conditional updates with concurrent requests, transaction rollback and production process restart. Keep protocol/state logic independent of UI.

- [ ] Audit successes, denials, expiry, cancellation, invalid signatures and revocation. Redact browser nonces, device tokens, private keys, session/refresh tokens and any future scan secrets/grants.

## Phase E — Release evidence

Extend the existing Rust tests, `test/` Hurl/security scripts and SDK test commands; add a release runner only when it orchestrates real checks. There is no assumed `cargo xtask certify` command.

| Required scenario | Evidence / expected result |
|---|---|
| Valid enrolled Android + correct match | Exactly one completion; MFA still enforced |
| Bad signature, wrong number, wrong nonce, revoked device | No authentication |
| Expired, denied or cancelled intent; guessed ID/code alone | No authentication; no reactivation |
| Replayed scan, signature, approval or completion | Safe rejection/idempotence; no duplicate session |
| Mixed approve/deny/expiry/complete races (50 of each) | Consistent outcome; sessions created ≤ 1 |
| Two users/devices/browsers/workspaces/clients | No identity or context leakage |
| DB failure, retry, restart, disconnect after consume | Defined recovery; no duplicate or false success |
| QR/parser malformed input, oversized bodies, unsupported values | Safe errors, no panic; fuzz/property regressions |
| Secret fixtures in logs and audit records | No credential leakage |
| Production-mode abuse tests | Configured limits enforced |
| Fresh clone and real Android walkthrough | Recorded prerequisites and reproducible success |

Add property tests for no terminal reactivation, no completion without approval and at most one consume. Run a documented 1,000-flow isolation test before stable; record hardware, configuration and results. Measure latency without promising unmeasured p95 targets.

Certification records the commit, configuration, commands, real-device details, pass/fail results and any skipped coverage. Missing Android/vendor/live-server evidence blocks the relevant gate; unit tests alone cannot certify it. Stable release requires the applicable gates in the [closeout checklist](./48_v0.2_exit_checklist.md), the matrix above, and no unresolved critical security issue or authentication bypass. Reference-APK distribution and library-consumption gates are tracked separately.
