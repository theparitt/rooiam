## Changes found by testing

- Android alpha.4 refreshes a review after background/foreground and activity recreation. It persists a decision-in-flight marker before sending and explains ambiguous outcomes after process death. It never restores a decision for automatic sending.
- SDK alpha.4 uses fixed-length HTTP streaming to prevent a buffered mutation replay after a dropped response. JVM and physical-phone lost-response tests cover this behavior.
- Phone completion previously rejected an external application's registered callback when creating an MFA challenge. The fix accepts only the exact active callback tied to the approved intent, user and browser binding. Ordinary MFA redirect policy is unchanged.
- An unsupported, oversized `surface` value could enter storage and logs. Start validation now permits only the tenant surface and bounds context fields before logging or consuming widget context.
- Nested identity-scope and device-endpoint rate limits shared a counter, counting requests twice. The outer scope now has its own per-path namespace; both budgets still apply.
- The separate Play build uses `com.rooiam.reference`; the existing local app keeps `com.rooiam.mobile`. A locally signed alpha.5 app bundle built and linted with API 36/AGP 8.10.1/Gradle 8.11.1. Package/version/target in its generated bundle manifest are `com.rooiam.reference` / code 5 / API 36; `jarsigner` verified the bundle.
