### Separate reference distribution track

`02-APP1`: verify installation/update of the distributed reference APK with Play Protect enabled. Required to claim that distribution path is ready; **not a prerequisite for compiling or consuming the SDK in another app**. Integrators own package, signing, distribution and vendor projects. The SDK must substantiate its own protocol/storage/policy behavior. Do not block unrelated library work on reference distribution, or drop the gate for a distribution path being advertised.

## Reproduction entry points

- From `rooiam-sdk/android`: `./gradlew assembleRelease testDebugUnitTest lintDebug assembleDebugAndroidTest publishReleasePublicationToLocalPreviewRepository`.
- From `rooiam-examples/example-5-android-reference-app`: `./gradlew assembleDebug lintDebug`.
- From repository root, after publication: `bash test/android-sdk-consumer.sh`.
- `test/reference-app-phone-browser.mjs`: real disposable API/Chromium with a simulated signing device; prerequisites and server checks are in [the runbook](../../test/device-login.md).
- `test/device-login-vendor-failures.mjs`: isolated strict-policy synthetic devices exercising a live invalid Google token and a missing verifier. Its guard requires a **separate PostgreSQL instance on 127.0.0.1:15485**; `ROOIAM_MODE=test` always selects a database named `rooiam_test`, whatever name appears in the configured URL.
- Hardware: [reference README](../../rooiam-examples/example-5-android-reference-app/README.md) and [SDK guide](../../rooiam-sdk/android/README.md). An instrumented APK build does not count as execution.

**Restart warning:** `ROOIAM_MODE=test` wipes/reseeds data on startup. It cannot prove production restart persistence. Use an isolated persistence-preserving configuration for that test. Back up the active walkthrough database before a test-mode restart; preserve the enrolled phone's server record.

Keep the public production/distribution track explicit: replace local operator ADC with unattended workload identity, deploy on the intended production host, decide supported Android/package scope and complete any external release approval. The user explicitly requested a simulated second developer because they work alone; do not repeatedly block on recruiting someone else or call the simulation independent. Preserve the new `phone-test.rooiam.com` enrollment and keep the certification package separate from the debug app.

0.3 design may proceed alongside this queue. Stable action approval depends on the device trust and recovery behavior it uses. Follow the [0.3 plan](./47_v0.3_sensitive_action_approval.md); do not turn the 0.2 login intent into an action executor.
